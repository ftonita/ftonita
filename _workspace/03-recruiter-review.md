## Раунд 3: переработанный набор из 5 репозиториев, 8.5/10
Что сильно:
- Каждый репозиторий закрывает конкретную строку CV и показывает инженерное мышление, а не набор конфигов: у `pipeline-platform` JSON Schema + генератор + 135 тестов + проверка по официальной схеме GitLab CI; у `vault-migration-toolkit` идемпотентность, CAS, ledger без значений секретов; у `access-as-code` 11 правил с граничными случаями; у `opsbot` модель угроз и правило двух человек; `release-bottleneck-analyzer` отвечает на вопрос «где теряется время».
- Везде раздел «What is verified / Not verified». Это редкость, рекрутер и интервьюер это ценят.
- Данные синтетические, это прямо сказано: нет риска утечки и вопросов от работодателя.

Что нашёл сам при сборке (все исправлено):
- `pipeline-platform`: PyYAML читает ключ `on:` как `true`, конфиг ломался. Ключ переименован в `refs`, добавлен тест на эту ловушку.
- `vault-migration-toolkit`: повторный `apply` доверял леджеру и не замечал ручной правки в Vault. Теперь идемпотентность определяется сравнением с Vault.
- `access-as-code`: даты в YAML становились объектами `date` и не проходили схему. Загрузчик оставляет строки.
- `release-bottleneck-analyzer`: ошибка `zip(strict=True)` в расчёте стадий поймана тестами.
- Несколько слабых тестов (всегда истинные условия) заменены осмысленными.

## Раунд 4: что мешает 9-10/10 (нужен ты)
1. **CI на GitHub ещё не запускался.** Я проверил локально (349 тестов на Python 3.13, те же на 3.11; `ruff`; схема GitLab CI), но не `docker build`, не Helm, не реальный Vault/Alertmanager/Telegram/GitLab runner. Первые прогоны CI могут покраснеть: это нормально, исправь обычным коммитом.
2. **Прочитай каждый репозиторий и запусти.** Код написан с ИИ; на интервью спросят «почему так». Используй `05-interview-prep.md`. Если что-то не можешь объяснить, упрости или убери.
3. **Terraform отсутствует** среди опубликованного, хотя это первая строка CV. Вернуть из `archive/` после локальной проверки `terraform validate`.
4. **Pinned и мусорные репозитории**: API не позволяет менять pinned; вручную.
5. **Нет ни одного реального запуска на настоящих данных.** Честно сказано в README; чтобы снять вопрос, прогони `release-bottleneck-analyzer` на выгрузке своих MR (без публикации результатов).

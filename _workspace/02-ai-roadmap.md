# 2. План развития GitHub с использованием ИИ

Принцип: **ИИ пишет черновик и ищет дыры, ты отвечаешь за каждое утверждение**. Во всех репозиториях только то, что реально умеешь объяснить на интервью.

## Фаза 0. Сейчас (неделя 1): витрина
1. Смержить README профиля (ветка `claude/wonderful-noether-bxfgn4`), без папки `_workspace`.
2. Запустить `_workspace/publish.sh` (создаст 4 репозитория, топики, описания), затем закрепить их.
3. Первый запуск CI: **vault-rbac-onboarding** и **terraform-hybrid-iac** я не мог прогнать здесь (нет Docker и доступа к Terraform Registry). Если CI покраснеет, это нормальный первый пул-реквест на исправление, не скрывай.
4. Архивировать мусор (см. аудит).

## Фаза 1 (недели 2-5): недостающее ядро CV
| Репозиторий | Что показывает | Как использовать ИИ |
|---|---|---|
| **gitops-argocd-helm** | Helm-чарт + ArgoCD app-of-apps, окружения через values, `helm lint` + `kubeconform` в CI | Генерация шаблонов чарта, затем ручная проверка на kind |
| **observability-stack** | VictoriaMetrics + Prometheus + Grafana (provisioned dashboards) + алерты, `docker compose up` | ИИ пишет правила алертов, ты проверяешь PromQL на реальных метриках |
| **log-pipeline** | Filebeat → Kafka → OpenSearch в compose | Черновик конфигов, нагрузочный тест скриптом |
| Python-утилита | Например, CLI аудита Vault-политик или экспортёр метрик | Тесты и типизация через ИИ |

## Фаза 2 (недели 6-12): глубина и доказательства
- В каждом репозитории: тесты в CI (Molecule для Ansible, `terraform test`, `kubeconform`), Dependabot/Renovate, релизы с тегами (SemVer).
- Короткие статьи/ADR в `docs/`: «Почему Patroni, а не repmgr», «Как мы мигрировали 10+ команд в Vault» (без внутренних данных). Это то, что рекрутеры цитируют на интервью.
- Contributing: 2-3 PR в чужие open-source DevOps-проекты (баг в Helm-чарте, документация). ИИ помогает искать good-first-issue и понять кодовую базу.

## Рабочий цикл с ИИ (повторяемый)
1. **Спецификация**: пишешь 5-10 строк «что должно получиться и как проверить».
2. **Черновик**: ИИ генерирует каркас.
3. **Проверка машиной**: линтеры и CI (`terraform fmt/validate`, `ansible-lint --profile production`, `yamllint`, `shellcheck`, `gitleaks`). Ни одного коммита с красным CI.
4. **Проверка человеком**: ты запускаешь на реальном стенде, правишь, пишешь в README только то, что воспроизвёл.
5. **Ревью-итерация**: просишь ИИ сыграть рекрутера/staff-инженера и найти слабые места; фиксишь.

## Правила безопасности
- Никакого кода, хостов, названий систем и данных работодателя. Только обезличенные паттерны.
- Секреты только в примерах-заглушках; перед каждым публичным пушем `gitleaks detect`.
- README не должен обещать то, чего нет в коде (чекбоксы Roadmap честно пустые).

## Поддержание активности (устойчиво, без накрутки)
1 содержательный коммит или PR в неделю; релиз раз в месяц; обновление README профиля раз в квартал по метрикам CV.

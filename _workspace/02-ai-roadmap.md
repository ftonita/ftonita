# 2. План развития GitHub с использованием ИИ

Принцип: **ИИ пишет черновик и ищет дыры, ты отвечаешь за каждое утверждение.** В публичных репозиториях только то, что ты можешь объяснить на интервью (см. `05-interview-prep.md`).

## Фаза 0 (неделя 1): витрина, 5 репозиториев
| Репозиторий | Покрывает строку CV |
|---|---|
| `pipeline-platform` | стандартизация пайплайнов для 5+ команд, GitLab CI, Vault, Nexus, Ansible/Helm/ArgoCD |
| `vault-migration-toolkit` | миграция 10+ команд в Vault, 1000+ секретов |
| `access-as-code` | least-privilege для 50+ разработчиков |
| `release-bottleneck-analyzer` | сокращение цикла релиза (14 → 3-4 дня) |
| `opsbot` | Telegram-боты (aiogram), автоматизация процессов |

Шаги: (1) прочитать и запустить каждый репозиторий самому; (2) `_workspace/publish.sh`; (3) дождаться CI на GitHub и починить красное; (4) закрепить 5 репозиториев; (5) заархивировать мусор (см. аудит); (6) смержить только `README.md`, без `_workspace/`.

## Рабочий цикл с ИИ
1. **Спецификация**: 5-10 строк «что должно получиться и как проверить».
2. **Черновик**: ИИ генерирует каркас и тесты.
3. **Проверка машиной**: `ruff`, `pytest`, `yamllint`, схема GitLab CI, CI в GitHub. Красное не мержим.
4. **Проверка человеком**: ты запускаешь на реальном стенде и правишь; README описывает только воспроизведённое. Раздел «What is verified / Not verified» обязателен.
5. **Ревью-итерация**: ИИ играет рекрутера и staff-инженера, ищет слабые места, ты фиксишь.

## Правила безопасности
- Никакого кода, хостов, названий систем и данных работодателя. Только синтетика и обезличенные паттерны (во всех пяти репозиториях так и сделано).
- Перед каждым публичным пушем `gitleaks detect`.
- Не заявлять в README то, что не запускалось.

## Поддержание активности
1 содержательный коммит или PR в неделю, релиз раз в месяц, обновление README профиля раз в квартал.
